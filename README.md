Вариант 6. Репертуар театра и продажа билетов.

Это продолжение второй лабораторной. В приложение добавлена база H2 и операции с билетами и показами. Используются Java 17 и Spring Boot.

## Что хранится в базе

Спектакли: название, длительность и возрастное ограничение.
Залы: название и количество мест.
Показы: какой спектакль идёт, в каком зале, время начала, цена и статус.
Пользователи: имена покупателей.
Билеты: показ, место, покупатель, статус, цена покупки и сумма возврата.

У одного спектакля может быть несколько показов. Каждый показ проходит в одном зале. Билет относится к конкретному показу и пользователю. Например, удалить зал нельзя, пока на него ссылаются показы. Занять одно место двумя действующими билетами тоже нельзя.

Для всех пяти сущностей доступны просмотр, создание, изменение и удаление через REST API.

## Что можно сделать

1. Забронировать группу соседних мест. Можно выбрать от 1 до 100 мест. Если хотя бы одно занято, весь заказ отменяется.
2. Купить забронированный билет. В билете сохраняется цена показа на момент покупки. Повторная покупка не допускается.
3. Вернуть купленный билет до начала показа. Записывается полная сумма возврата, а место снова становится свободным.
4. Отменить будущий показ. Вместе с ним отменяются брони и купленные билеты. Для купленных билетов записывается возврат денег.
5. Завершить показ после его окончания. Купленные билеты получают статус ИСПОЛЬЗОВАН, оставшиеся брони отменяются.

Бронировать, покупать и возвращать билеты можно только до начала запланированного показа. Время проверяется на сервере. Покупка и возврат здесь учебные, настоящей оплаты нет.

Все изменения одной операции сохраняются вместе. Если возникает ошибка, они откатываются. При отмене и завершении обновляются сразу показ и его билеты.

## Как запустить

1. Открыть проект в IntelliJ IDEA 
2. Если `.env` ещё нет, сделать копию `.env.example` с именем `.env` и указать в ней два разных пароля.
3. Запустить класс `Лаба3`. Приложение работает по адресу `http://localhost:8082`.
4. Для проверки импортировать `Запросы.postman_collection.json` в Postman и запустить коллекцию целиком через Run. Запросы идут по порядку: создают записи, выполняют операции, проверяют ошибки и удаляют свои тестовые данные.

H2 загружается через Maven. База лежит в папке `данные` и сохраняется после остановки приложения.

Для запросов используется отдельный пользователь БД. Он может читать и менять записи, но не создавать и удалять таблицы. Учётная запись администратора нужна при запуске для подготовки базы и прав. Пароли хранятся в `.env`.
